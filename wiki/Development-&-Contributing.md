# Development & Contributing Guide

This guide covers everything you need to know to set up a local development environment, make modifications, debug within the Figma Desktop client, and contribute to **GitLayer**.

---

## Development Environment Setup

### 1. Prerequisites
- **Node.js** (v18.0.0 or higher recommended)
- **npm** (v9.0.0 or higher)
- **Figma Desktop App** (required for local plugin manifest import and testing)

### 2. Installation
Clone the repository and install all development dependencies:

```bash
git clone https://github.com/theabhishekarmagi/GitLayer.git
cd GitLayer
npm install
```

## Build and Watch Commands

All build scripts are defined in `package.json`:

| Command | Purpose |
| :--- | :--- |
| `npm run build` | Compiles `code.ts` into `code.js` via the TypeScript compiler (`tsc`). |
| `npm run watch` | Runs `tsc -p tsconfig.json --watch` to automatically compile `code.ts` on save. |
| `npm run lint` | Analyzes all TypeScript and JavaScript files with ESLint. |
| `npm run lint:fix` | Automatically fixes auto-fixable ESLint violations. |

> [!IMPORTANT]
> Figma executes `code.js`, **not** `code.ts`. Whenever you modify `code.ts`, you must run `npm run build` or have `npm run watch` active in your terminal.

## Testing and Debugging in Figma

### 1. Loading the Plugin
1. Open the **Figma Desktop App**.
2. Open any test design file.
3. Open the main menu and go to:  
   **Plugins** > **Development** > **Import plugin from manifest...**.
4. Select `manifest.json` located in the root of this project.

### 2. Opening Developer Tools
You can inspect both the Figma sandbox and the UI iframe using Chromium Developer Tools:
- Right-click anywhere in the Figma window and select **Inspect** (or press `Cmd + Option + I` on macOS / `Ctrl + Shift + I` on Windows).
- **Inspecting `code.js`**: Console logs from `code.ts` (e.g., `console.log`) appear directly in the main Figma console.
- **Inspecting `ui.html`**: Right-click directly inside the GitLayer plugin panel and choose **Inspect**. This opens a dedicated DevTools window for the iframe where you can inspect DOM elements, check network calls (`api.github.com`), and view UI errors.

### 3. Rapid Iteration
- To restart the plugin after compiling changes:
  - Press `Cmd + Option + P` (macOS) or `Ctrl + Alt + P` (Windows) to run the last-used plugin instantly.
  - Or right-click in the canvas and choose **Plugins** > **Run last plugin**.

## Code Style and Conventions

- **TypeScript**: Strict typing is enabled in `tsconfig.json`. Ensure any new scene node interactions adhere to `@figma/plugin-typings`.
- **ESLint**: Run `npm run lint` before committing to ensure adherence to `@figma/eslint-plugin-figma-plugins`.
- **Separation of Concerns**:
  - Keep canvas manipulation, font loading, and node geometry calculations in `code.ts`.
  - Keep DOM rendering, styling, animations, and network I/O in `ui.html`.
  - Ensure message types passed between the two threads are strictly documented in the message protocol.

## Contribution Workflow

1. **Fork the Repository**: Create a personal fork on GitHub.
2. **Create a Feature Branch**:
   ```bash
   git checkout -b feature/awesome-feature
   ```
3. **Make Your Changes**: Write clean, commented code and verify build compilation:
   ```bash
   npm run build
   ```
4. **Test in Figma**: Verify functionality across diverse Figma node types (Auto-layout, frames, vectors, images, gradients).
5. **Submit a Pull Request**: Provide a detailed description of the problem solved, any UI changes, and how you tested the feature.
